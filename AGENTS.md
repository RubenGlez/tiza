# AGENTS.md

Canonical agent-facing context for the Tiza repo. Read this before exploring individual files.

## What this repo is

Tiza is a TypeScript monorepo (pnpm workspaces) implementing a **Shared Context Store (SCS)** for multi-agent MCP systems. Two published packages: `@tiza/core` (zero-dependency store + runtime) and `@tiza/mcp` (stdio MCP server). A benchmark app lives in `apps/code-review-mcp/`.

## Install, build, test

```bash
# Install all workspace deps
pnpm install

# Build @tiza/core (required before running MCP typechecks)
pnpm --filter @tiza/core build

# Tests
pnpm --filter @tiza/core test
pnpm --filter @tiza/mcp test

# Typecheck
pnpm --filter @tiza/core typecheck
pnpm --filter @tiza/mcp typecheck

# Lint (biome)
pnpm lint

# Benchmark (requires API key)
ANTHROPIC_API_KEY=... pnpm benchmark
```

## Conventions

- `@tiza/core` has zero runtime dependencies — only Node.js built-ins (`crypto`, `fs`, `path`). Do not add external deps.
- `@tiza/mcp` uses `workspace:*` to reference `@tiza/core`. Always rebuild core (`pnpm --filter @tiza/core build`) before running MCP typecheck.
- Store entries are append-only — no update or delete operations.
- `TizaRuntime` is the multi-run layer; `createStore()` is the single-run layer. Prefer `TizaRuntime` for server/MCP usage, `createStore()` for embedded/scripting usage.
- Benchmark results in `apps/code-review-mcp/benchmark-results/` are committed artifacts — do not delete them.
- `.harness/` is gitignored — internal docs only, never link to from public files.

## Non-obvious constraints

- After editing `packages/core`, run `pnpm --filter @tiza/core build` before typechecking `packages/mcp` — the MCP resolves `@tiza/core` via its workspace symlink to the built `dist/`.
- The benchmark uses real MCP stdio transport — it spawns the MCP server as a child process via `tsx`. Requires `tsx` in devDependencies.
- `FilePersistenceBackend` uses lock files (`*.lock`) for atomic writes — do not add concurrent write logic without accounting for this.
- `tiza_init` MCP tool always resets the "default" run — it exists solely for benchmark backwards compatibility. New code should use `tiza_open_run`.

## Do not edit

- `apps/code-review-mcp/benchmark-results/*.json` — committed benchmark artifacts
- `packages/core/dist/` — build output, regenerated by tsup
- `pnpm-lock.yaml` — managed by pnpm
